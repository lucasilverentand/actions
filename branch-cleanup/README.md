# Branch cleanup

Find old branches whose exact current tip belongs to a merged PR into the current default branch. Preview is the default; deletion requires an explicit opt-in.

Copy the [example workflow](../docs/examples/branch-cleanup.yml). Run it on a schedule or by manual dispatch, from the repository's default branch. The action refuses PR events and non-default-branch runs.

## Eligibility and safeguards

Both the merge and the tip commit's author and committer dates must be at least 30 days old by default. The current tip must exactly match a merged PR's head SHA. This also supports squash and rebase merges while retaining branches with new unmerged commits.

Cleanup retains:

- The default branch and common long-lived names: `main`, `master`, `trunk`, `dev`, `develop`, `development`, `staging`, `production`, and `gh-pages`.
- Branches under `release/`, `releases/`, `hotfix/`, and any additional configured prefixes.
- Protected branches, branches with any active rules, and branches used as a head or base of an open PR.

Archived, disabled, and fork repositories are excluded. API failures stop the run. Previews report all candidates even when their count exceeds the deletion limit. A deletion run above that limit aborts before removing anything.

Before each deletion, the action rechecks repository state, the branch tip, rules, merge evidence, and open PRs. Git deletion uses `--force-with-lease` with the inspected SHA, so a concurrent tip update prevents deletion. The open-PR check and deletion cannot be one GitHub transaction: a PR can open between them. Protect essential branches or retain them by prefix. A network failure can also stop a run after some eligible branches have already been deleted. See the [security policy](../.github/SECURITY.md).

## Enable deletion

First run previews with Contents read and Pull requests read. Review the job summary, then set `dry-run: 'false'` and grant that job Contents write. Keep the concurrency group from the example to prevent overlapping cleanup runs.

GitHub's “automatically delete head branches” setting handles ordinary merged PRs immediately. This action is a delayed sweep for branches that remain; it does not delete every branch merely because it is old.

## Interface

| Input | Default | Meaning |
| --- | --- | --- |
| `token` | `${{ github.token }}` | Repository-scoped credential |
| `dry-run` | `true` | Preview only; set `false` explicitly to delete |
| `minimum-age-days` | `30` | Minimum age of merge and commit dates; accepts 7–3650 |
| `max-deletions` | `10` | Abort deletion if candidate count exceeds this limit; previews still report all candidates; accepts 1–100 |
| `keep-prefixes` | `[]` | JSON array of additional retained prefixes, such as `["support/", "stable/"]` |
| `inspection-concurrency` | `4` | Concurrent branch eligibility reads, from 1–8; deletion and its rechecks remain serial |

Built-in exclusions always apply. Inputs cannot disable them.

The `candidates` output is a JSON array of branch names and expected SHAs. `candidate-count` is the number eligible; `deleted-count` is the number actually deleted. Results also appear in the job summary.

## Files

`action.yml` is the interface; `src/index.mjs` implements selection and deletion. `test/` covers exclusions, failures, rechecks, and a real local Git lease race. `dist/index.mjs` is generated by the root build command and runs without a checkout of the consuming repository.

Deletion requires Git 2.31 or newer. The action clears inherited repository-routing variables, disables Git templates and uses a private empty configuration, while preserving the runner's TLS configuration. Preview has no Git dependency.
